# Приёмка работ

Отчёт лабораторной хранится в приложении и резервной копии. Кнопка сохранения отчёта записывает Markdown в workspace. Это дневник доказательств, не автопроверка и не сертификат. Ревью проводит ментор, коллега или сам ученик по реальным артефактам. ИИ не подтверждает запуск без результатов.

Для каждого критерия запиши: что проверялось, файл/коммит, команда, результат, вывод. Скриншот зелёной строки без команды и списка тестов недостаточен.

## Рубрика итогового проекта

Каждый пункт оценивается 0/1/2: отсутствует или неверно / работает с подсказкой или неполным доказательством / выполнено самостоятельно и объяснено по артефакту.

| Навык | Доказательство для 2 |
|---|---|
| Проектирование | Матрица рисков, уровней, границ и независимых ожиданий |
| Python | Объяснение типов, функций, исключений и импортов; новое преобразование без генерации |
| pytest | Параметризация, фикстуры, cleanup после падения, независимый порядок |
| API | Реальные CRUD, контракт, негативные случаи и чужой пользователь |
| UI | Устойчивые локаторы, expect, независимые сценарии, trace падения |
| SQL | JOIN, пользователь без заказов, параметры, временная база |
| Git и CI | PR, разрешённый конфликт, красный и зелёный run с артефактом |
| Диагностика | Различены продукт, тест, данные и окружение на конкретных сбоях |
| ИИ | Найдены ошибки генерации, проверены методы, объяснены исправления |
| Перенос | Новое требование выполнено через неделю без готового решения |

Учебный ориентир: минимум 16/20 без нулей; Python, pytest, API, UI и диагностика обязательно по 2. Это внутренняя рубрика, не прогноз трудоустройства. При пробеле повтори соответствующую лабораторную с новыми данными.

Блокеры независимо от баллов: тест зелёный на внесённом дефекте; expected получен из actual без независимого правила; зависимость от порядка; неработающий cleanup; CI игнорирует ошибки; автор не объясняет код.

## Защита на 60-90 минут

1. Из чистой папки запусти проект по README.
2. Объясни один API- и один UI-тест, включая данные и очистку.
3. Разбери незнакомое падение: гипотеза, эксперимент, причина.
4. Добавь новый граничный случай без готового кода ИИ. Документацией пользоваться можно.
5. Покажи три обнаруженных контролируемых дефекта и восстановленный код.
6. Исправь замечания ревью. Через неделю повтори перенос навыка.

Docker, PostgreSQL, async, очереди, нагрузка, мобильные тесты и Selenium здесь не изучаются глубоко. Их добавляют по стеку команды после основного маршрута.
