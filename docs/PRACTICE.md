# Практикум на учебном магазине

Запусти курс и открой `/shop`. Все суммы в этой версии — целые GEL; реальных платежей нет.

| ID | Предусловие и действия | Ожидаемый результат | Уровень |
|---|---|---|---|
| TC-001 | Открыть магазин | Видно сообщение «Пока пусто» | UI |
| TC-002 | Добавить блокнот | Количество 1, сумма 500 | UI |
| TC-003 | Добавить блокнот, поставить 2 | Количество 2, сумма 1000 | UI / логика |
| TC-004 | Добавить блокнот, поставить 99 | Сумма 49500 | UI |
| TC-005 | Добавить блокнот, поставить 0 | Сообщение валидации, сумма «—» | UI |
| TC-006 | Добавить блокнот, поставить -1 | Сообщение валидации | UI |
| TC-007 | Добавить блокнот, поставить 1.5 | Сообщение валидации | UI |
| TC-008 | Добавить блокнот, очистить | Видно «Пока пусто», поле количества скрыто | UI |
| TC-009 | GET /shop/api/products | 200, список из двух товаров | API |
| TC-010 | GET /shop/api/products | id — целые, имена непустые, цены положительные | API |
| TC-011 | GET /shop/api/missing | 404 | API |
| TC-012 | Перезагрузить страницу с товаром | Корзина пустая: в этой версии она не сохраняется | UI |

Для каждого кейса: запиши выбранный уровень проверки; подготовь независимое состояние; напиши действия и проверки; запусти дважды; сохрани осмысленный коммит. Не проверяй расположение элементов по пикселям, если требование касается суммы.

Требование к повторному нажатию «Добавить блокнот» в v0.1: количество сбрасывается до 1. Это учебное упрощение, не обычное поведение полноценного магазина.

## Саморевью

- Название объясняет проверяемое поведение?
- Есть проверка результата, а не только успешного клика?
- Тест проходит отдельно и в группе?
- Нет фиксированных sleep и зависимости от предыдущего теста?
- При падении понятно, какое ожидание нарушено?
- Конфигурация отделена от секретов?
