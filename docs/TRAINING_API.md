# Контракт тренировочного API

На Windows проще открыть `start_training_api.bat`: он запускает API и открывает `/health` в браузере. Ожидаемый ответ: `{"status":"ok"}`. Окно API нужно оставлять открытым. Никакой отдельный урок автоматически не начинается: задания находятся в лабораторной 25 на сайте курса.

Запуск из папки курса: `python training_api.py`. Адрес по умолчанию `http://127.0.0.1:8767`. Другой порт: `--port 8768`. Данные в памяти, перезапуск их удаляет. Это отдельный стенд: UI магазина не читает его заказы.

`GET /health` доступен без авторизации: 200, `{"status":"ok"}`.

Для остальных запросов передай `Authorization: Bearer alice` или `Authorization: Bearer bob`. Это искусственные учебные личности, не настоящие секреты. Другие значения и отсутствие заголовка дают 401 `{"error":"unauthorized"}`. Стенд слушает только loopback и не предназначен для публикации.

| Метод и путь | Данные | Успех |
|---|---|---|
| GET /orders | Нет | 200, `{"orders":[...]}` только своего пользователя |
| POST /orders | JSON `{"quantity":2}` | 201, новый заказ |
| GET /orders/{id} | Нет | 200, существующий заказ |
| PATCH /orders/{id} | JSON `{"quantity":3}` | 200, изменённый заказ |
| DELETE /orders/{id} | Нет | 200, `{"deleted":id}` |

Заказ: `{"id":1,"owner":"alice","quantity":2,"total":1000}`. id генерируется сервером, цена фиксирована 500, total = quantity * 500. Не предполагай, что первый заказ твоего теста получит id=1.

Количество: именно целое 1..99 включительно. Дробные, строки, bool, null, отсутствующее поле, некорректный JSON и тело больше 4096 байт отклоняются: 400 `{"error":"invalid_quantity"}`. Дополнительные поля игнорируются. Неверный PATCH не меняет заказ; неверный POST не создаёт его.

Отсутствующий id: 404 `{"error":"not_found"}`. Чужой существующий заказ: 403 `{"error":"forbidden"}` для GET/PATCH/DELETE. Эти отказы не меняют данные. DELETE уже удалённого заказа даёт 404. Список не включает чужие заказы. Поддерживаемый методом обработчика запрос к ресурсу с неподходящим методом даёт 405 `{"error":"method_not_allowed"}`; неизвестные HTTP-методы могут возвращать стандартный 501 сервера.

Порядок проверок: авторизация, путь и метод, существование и владелец, тело. Поэтому PATCH чужого заказа с плохим телом вернёт 403. Не переноси эту учебную модель ошибок на иной сервис без чтения его контракта.

Пример жизненного цикла с cleanup находится в `examples/test_orders.py`. Сначала напиши свой тест по контракту, потом сравни. Клиент обязан задавать timeout. Для ошибок соединения используй остановленный стенд, для детерминированного тайм-аута mock.
