# QA Path — Manual → Python AQA

Локальный интерактивный курс на русском: короткое объяснение → разобранный пример → ассоциация → самостоятельная задача → проверка.

**Для кого:** Manual QA без опыта программирования. **Результат первого маршрута:** базовый Python, первые тесты, понимание Git, API, SQL и UI, самостоятельная автоматизация небольшого тест-кейса.

Это первая рабочая версия, а не законченная программа подготовки к любой AQA-вакансии. Она содержит 14 уроков, встроенный редактор Python, автопроверку, подсказки, историю попыток, сохранение в SQLite и учебный магазин. Практика Git и UI внутри кабинета проверяет основы; реальный запуск pytest и Playwright выполняется отдельно по инструкции.

## Скачать и запустить

Нужен **Python 3.11 или новее**. Установщик: https://www.python.org/downloads/ . На Windows включи `Add python.exe to PATH`. Проверь в новом терминале: `python --version`. Если команда открывает Microsoft Store, попробуй `py --version` или установи Python с официального сайта.

### Без Git

В репозитории нажми **Code → Download ZIP**, распакуй архив и открой терминал в распакованной папке с `app.py`. Доступ к приватному репозиторию требует входа в GitHub.

```powershell
python app.py
```

Если Python доступен командой `py`, используй `py app.py`. На Windows также можно дважды нажать `start.bat`. Откроется http://127.0.0.1:8765 . Для самого курса не нужны pip, Node.js, Docker или платные API. После скачивания курс работает без интернета.

### Через Git

```powershell
git clone https://github.com/anchorbug/qa-path.git
cd qa-path
python app.py
```

Для приватного репозитория Git попросит авторизацию. Не вставляй пароль или токен в URL репозитория.

Остановка: `Ctrl+C` в терминале. Если порт занят: `python app.py --port 8766`. Без автоматического открытия браузера: `python app.py --no-browser`. При другом порте поменяй адрес в учебных API/UI-примерах.

## Как проходить урок

1. Открой «Разобраться». Прочитай цель и объяснение.
2. Пройди пример по строкам. Скажи своими словами, что получает и возвращает каждая операция.
3. Открой «Попробовать», допиши код и нажми «Проверить решение».
4. Прочитай отдельные проверки. При исключении начни с последней строки traceback.
5. Если застрял, открой одну подсказку. Последняя подсказка иногда содержит почти готовое решение; её использование сохраняется.
6. После успеха измени входные данные мысленно и объясни, каким будет результат.

Открывать уроки можно в любом порядке. Галочка означает, что задание хотя бы раз прошло проверки; последующие неудачные попытки не стирают достижение. Количество подсказок помогает отличить самостоятельное выполнение от выполнения с помощью. Автопроверка не оценивает всю читаемость и архитектуру кода.

## VS Code и PyCharm

Для первых упражнений редактор устанавливать необязательно — он уже есть в браузере.

**VS Code:** установи редактор с https://code.visualstudio.com/ и расширение Python от Microsoft. Выбери `File → Open Folder` и папку проекта. Команда `Python: Select Interpreter` выбирает используемый Python.

**PyCharm:** открой папку проекта, выбери интерпретатор Python в настройках проекта. Для последующей практики укажи интерпретатор из `.venv`.

Кнопка **«Сохранить файл для IDE»** записывает код в `workspace/<id-урока>.py`. Она заменяет существующий файл этого урока. Отредактируй его в IDE, сохрани и нажми **«Прочитать из файла»**, затем «Проверить решение». Двусторонней автоматической синхронизации нет: это явный обмен файлами.

## Настоящий pytest и Playwright

Для внешних библиотек создай отдельное окружение. Команды ниже для Windows, запускать из папки проекта:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\python.exe -m pytest examples/test_cart.py -v
```

Окружение — отдельная папка с Python и библиотеками проекта. Прямой вызов `.venv\Scripts\python.exe` позволяет не менять политику запуска PowerShell. На macOS/Linux вместо него используй `.venv/bin/python`.

Для API и UI оставь `python app.py` работающим в первом терминале, а во втором выполни:

```powershell
.venv\Scripts\python.exe -m pytest examples/test_api.py -v
.venv\Scripts\python.exe -m pytest examples/test_shop.py -v --browser chromium
```

В `examples/` есть рабочие примеры. Сначала попробуй решить задачу сам, потом сравни. Учебный магазин доступен по `/shop`, каталог — по `/shop/api/products`. Текущий магазин поддерживает добавление блокнота, изменение количества и очистку корзины; авторизация и оформление заказа запланированы для расширения.

## Прогресс и резервная копия

- `data/progress.sqlite3` — решения, достижения, подсказки и история попыток.
- `workspace/` — файлы для IDE.
- Кнопка «Резервная копия» скачивает JSON с текущими решениями и прогрессом. История отдельных попыток туда не входит.
- «Восстановить» заменяет код соответствующих уроков и объединяет достижения; другие уроки не удаляются. Файл не выполняется автоматически.
- Для полного переноса закрой приложение и скопируй `data/` и `workspace/`.

Личные решения и база исключены из Git. Для собственного портфолио создай отдельный репозиторий решений; не убирай исключение `data/`.

## Что внутри

```text
app.py               HTTP-сервер, API, SQLite, запуск проверок
course.py            содержание уроков и проверки
runner.py            отдельный процесс выполнения упражнения
static/              интерфейс и учебный магазин
examples/            реальные примеры pytest, API и Playwright
tests/               проверки приложения и курса
docs/                методика, тест-кейсы, дальнейшая программа
.github/workflows/   CI самого проекта
```

Приложение слушает только `127.0.0.1`. Изменяющие запросы требуют токен страницы. **Учебный Python выполняется с правами текущего пользователя, это не защищённая песочница.** Ограничение времени останавливает прямой процесс, но не является защитой от намеренно вредоносного кода и его дочерних процессов. Используй приложение только локально и запускай свои учебные решения. Не публикуй этот сервер в интернете.

## Проверка разработки

Без сторонних пакетов:

```powershell
python -m unittest discover -s tests -v
```

Тесты используют отдельную временную базу. Они проверяют правильные решения, отказ пустым/ошибочным решениям, обнаружение внесённых дефектов, сохранение, импорт и API. GitHub Actions выполняет их после push и pull request. CI приложения не запускает автоматически решения из личной папки `workspace/`.

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| `python` не найден | Установить Python, открыть новый терминал, попробовать `py` |
| Окно сразу закрылось | Запустить `python app.py` из терминала и прочитать ошибку |
| Порт занят | Запустить с `--port 8766` |
| `ModuleNotFoundError: requests` | Установить requirements в выбранное окружение и запускать его Python |
| Playwright не находит браузер | Выполнить `python -m playwright install chromium` из окружения |
| API/UI-тест не соединяется | Убедиться, что app.py запущен и порт в примере совпадает |
| Кнопки просят обновить страницу | После перезапуска сервера обновить вкладку |
| Проверка прерывается через 8 секунд | Проверить бесконечный цикл, ввод input() и сетевые ожидания |
