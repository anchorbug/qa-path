# QA Path: Manual → Python AQA

Локальный интерактивный курс на русском: короткое объяснение → разобранный пример → ассоциация → самостоятельная задача → проверка.

**Для кого:** Manual QA без опыта программирования. **Целевой результат:** самостоятельный небольшой проект автотестов на Python/pytest/requests/Playwright, разбор падений и осмысленное использование ИИ. Достижение проверяется проектом и ревью.

Версия v0.2 содержит **34 учебных шага: 14 вводных упражнений с автопроверкой и 20 лабораторных в IDE**, включая итоговый проект. Лабораторные учат Python, pytest, HTTP/CRUD, Playwright, SQL, Git, CI, диагностике и проверке кода ИИ. Для них есть теория, пример, самостоятельная задача, критерии приёмки и отчёт с доказательствами. Сохранение отчёта не означает автоматическое подтверждение навыка.

Проходи курс по порядку. [Критерии итогового проекта](docs/ASSESSMENT.md) определяют готовность лучше числа прочитанных уроков. Время лабораторных включает практику; повторение и ревью могут занять больше. При 8-10 часах в неделю планируй несколько месяцев.

## Что именно запускать

- **Курс:** дважды нажми `start.bat` в распакованной папке. Не нужно открывать `launcher.py` двойным щелчком: Windows может открыть Python-файл в редакторе вместо запуска. Если браузер не открылся, перейди на http://127.0.0.1:8765 . При ошибке батник оставит окно открытым; скопируй его текст.
- **Уроки 01-14:** читай и пиши решение внутри сайта, нажимай «Проверить решение».
- **Файл `labs.py`:** хранит содержание лабораторных. Его отдельно не запускают; отсутствие окна при запуске нормально.
- **Лабораторные 15-34:** открой нужный урок на сайте. Прочитай объяснение и шаги, выполни задание в своей IDE и терминале. Вернись на сайт, заполни отчёт и отметь критерии. Кнопка отметки не запускает тесты.
- **Тренировочный API:** нужен для лабораторной 25, не для всего курса. Дважды нажми `start_training_api.bat`. Откроется страница `/health` с `{"status":"ok"}`. Это означает, что сервер работает. Это не отдельный сайт с упражнениями: запросы к нему отправляет твой код. Окно этого API оставляй открытым, остановка через `Ctrl+C`.
- **Готовые примеры:** `python -m pytest examples -v` из настроенного окружения сам поднимает временные серверы. Для этих примеров отдельно запускать API не нужно. UI-примерам нужен установленный Chromium.

Если видишь «адрес занят», сначала останови уже запущенную копию этого сервера. Ошибки фонового запуска курса записываются в `data/server.log`. После обновления файлов останови старый курс через `stop.bat`, затем запусти `start.bat` заново.

## Скачать и запустить

Нужен **Python 3.11 или новее**. Установщик: https://www.python.org/downloads/ . На Windows включи `Add python.exe to PATH`. Проверь в новом терминале: `python --version`. Если команда открывает Microsoft Store, попробуй `py --version` или установи Python с официального сайта.

### Без Git

В репозитории нажми **Code → Download ZIP**, распакуй архив и открой терминал в распакованной папке с `app.py`. Доступ к приватному репозиторию требует входа в GitHub.

```powershell
python app.py
```

Если Python доступен командой `py`, используй `py app.py`. На Windows дважды нажми `start.bat`: сервер запустится в фоне, окно CMD закроется само, курс откроется в браузере. Повторный запуск открывает уже работающий сервер этой копии. Для остановки используй `stop.bat`. Откроется http://127.0.0.1:8765 . Для самого курса не нужны pip, Node.js, Docker или платные API. После скачивания курс работает без интернета.

### Через Git

```powershell
git clone https://github.com/anchorbug/qa-path.git
cd qa-path
python app.py
```

Для приватного репозитория Git попросит авторизацию. Не вставляй пароль или токен в URL репозитория.

При прямом запуске `python app.py` окно терминала должно оставаться открытым: его закрытие или `Ctrl+C` останавливает сервер. При запуске через `start.bat` терминал не нужен; остановка через `stop.bat`. После перезагрузки компьютера снова запусти `start.bat`. Прогресс хранится на диске и от остановки не исчезает. Лог фонового запуска: `data/server.log`. Если порт занят: `python app.py --port 8766`. Без автоматического открытия браузера: `python app.py --no-browser`. При другом порте поменяй адрес в учебных API/UI-примерах.

## Как проходить урок

1. Открой «Разобраться». Прочитай цель и объяснение.
2. Пройди пример по строкам. Скажи своими словами, что получает и возвращает каждая операция.
3. Открой «Попробовать», допиши код и нажми «Проверить решение».
4. Прочитай отдельные проверки. При исключении начни с последней строки traceback.
5. Если застрял, открой одну подсказку. Последняя подсказка иногда содержит почти готовое решение; её использование сохраняется.
6. После успеха измени входные данные мысленно и объясни, каким будет результат.

Общий счётчик показывает выполненные шаги из 34. Под ним отдельно показаны задания с автопроверкой и лабораторные с самооценкой. Для лабораторной заполни отчёт и нажми «Работа выполнена: подтверждаю критерии». Отметку можно снять; она не заменяет ревью.

Открывать уроки можно в любом порядке. Галочка вводного упражнения означает, что оно хотя бы раз прошло проверки; последующие неудачные попытки не стирают достижение. Количество подсказок помогает отличить самостоятельное выполнение от выполнения с помощью. Автопроверка не оценивает всю читаемость и архитектуру кода.

## VS Code и PyCharm

Для первых упражнений редактор устанавливать необязательно: он уже есть в браузере.

**VS Code:** установи редактор с https://code.visualstudio.com/ и расширение Python от Microsoft. Выбери `File → Open Folder` и папку проекта. Команда `Python: Select Interpreter` выбирает используемый Python.

**PyCharm:** открой папку проекта, выбери интерпретатор Python в настройках проекта. Для последующей практики укажи интерпретатор из `.venv`.

Кнопка **«Сохранить файл для IDE»** записывает код в `workspace/<id-урока>.py`. Она заменяет существующий файл этого урока. Отредактируй его в IDE, сохрани и нажми **«Прочитать из файла»**, затем «Проверить решение». Двусторонней автоматической синхронизации нет: это явный обмен файлами.

## Настоящий pytest и Playwright

Для внешних библиотек создай отдельное окружение. Команды ниже для Windows, запускать из папки проекта:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\python.exe -m pytest examples/test_cart.py -v
```

Окружение: отдельная папка с Python и библиотеками проекта. Прямой вызов `.venv\Scripts\python.exe` позволяет не менять политику запуска PowerShell. На macOS/Linux вместо него используй `.venv/bin/python`.

Примеры API и UI теперь сами запускают временный локальный сервер через examples/conftest.py. Выполни:

```powershell
.venv\Scripts\python.exe -m pytest examples/test_api.py examples/test_orders.py -v
.venv\Scripts\python.exe -m pytest examples/test_shop.py -v --browser chromium
```

Для ручной API-практики запусти `python training_api.py` в отдельном терминале. [Контракт](docs/TRAINING_API.md) описывает CRUD, валидацию и учебных пользователей. Этот стенд не связан с корзиной UI.

В `examples/` есть рабочие примеры. Сначала попробуй решить задачу сам, потом сравни. Учебный магазин доступен по `/shop`, каталог: по `/shop/api/products`. Текущий магазин поддерживает добавление блокнота, изменение количества и очистку корзины; авторизация магазина и оформление заказа в UI не реализованы; права доступа тренируются в отдельном API.

## Прогресс и резервная копия

- `data/progress.sqlite3`: решения, достижения, подсказки и история попыток.
- `workspace/`: файлы для IDE.
- Кнопка «Резервная копия» скачивает JSON с текущими решениями и прогрессом. История отдельных попыток туда не входит.
- «Восстановить» заменяет код соответствующих уроков и объединяет достижения; другие уроки не удаляются. Файл не выполняется автоматически.
- Для полного переноса закрой приложение и скопируй `data/` и `workspace/`.

Личные решения и база исключены из Git. Для собственного портфолио создай отдельный репозиторий решений; не убирай исключение `data/`.

## Что внутри

```text
app.py               HTTP-сервер, API, SQLite, запуск проверок
course.py            вводные упражнения и проверки
labs.py              лабораторные, критерии и задания
training_api.py      отдельный локальный CRUD-стенд
runner.py            отдельный процесс выполнения упражнения
static/              интерфейс и учебный магазин
examples/            реальные примеры pytest, API и Playwright
tests/               проверки приложения и курса
docs/                методика, тест-кейсы, дальнейшая программа
.github/workflows/   CI самого проекта
```

Приложение слушает только `127.0.0.1`. Изменяющие запросы требуют токен страницы. **Учебный Python выполняется с правами текущего пользователя, это не защищённая песочница.** Ограничение времени останавливает прямой процесс, но не является защитой от намеренно вредоносного кода и его дочерних процессов. Используй приложение только локально и запускай свои учебные решения. Не публикуй этот сервер в интернете.

## Проверка разработки

Без сторонних пакетов:

```powershell
python -m unittest discover -s tests -v
```

Тесты используют отдельную временную базу. Они проверяют правильные решения, отказ пустым/ошибочным решениям, обнаружение внесённых дефектов, сохранение, импорт и API. GitHub Actions выполняет их после push и pull request. CI приложения не запускает автоматически решения из личной папки `workspace/`.

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| `python` не найден | Установить Python, открыть новый терминал, попробовать `py` |
| Окно сразу закрылось | Запустить `python app.py` из терминала и прочитать ошибку |
| Порт занят | Запустить с `--port 8766` |
| `ModuleNotFoundError: requests` | Установить requirements в выбранное окружение и запускать его Python |
| Playwright не находит браузер | Выполнить `python -m playwright install chromium` из окружения |
| API/UI-тест не соединяется | Убедиться, что app.py запущен и порт в примере совпадает |
| Кнопки просят обновить страницу | После перезапуска сервера обновить вкладку |
| Проверка прерывается через 8 секунд | Проверить бесконечный цикл, ввод input() и сетевые ожидания |
